# 受講生管理システム（StudentManagement）

受講生情報と受講コース情報を管理するためのWebアプリケーションです。
RaiseTech Javaフルコースの学習課題として作成し、Javaバックエンド開発における主要な技術スタック（Spring Boot / MyBatis / MySQL / REST API / テスト / CI/CD / AWSデプロイ）を一通り学習・実践することを目的としています。

## 💻 使用技術

| カテゴリ | 技術スタック |
| :--- | :--- |
| **言語** | Java 21 |
| **フレームワーク** | Spring Boot, MyBatis |
| **データベース** | MySQL (RDS), H2 Database (テスト用) |
| **ビルドツール** | Gradle |
| **APIドキュメント**| Swagger / OpenAPI |
| **テスト** | JUnit 5, Mockito |
| **CI/CD** | GitHub Actions |
| **インフラ / 運用** | AWS (EC2, RDS, ALB), systemd |

## ⚙️ 主な機能

* **受講生管理 (CRUD + 検索)**
  * 受講生の新規登録 / 詳細・一覧取得 / 情報更新
  * **複数条件による受講生検索**（柔軟なデータ抽出が可能）
  * **論理削除の導入**（実務を意識し、データを物理削除せず削除フラグで制御）
* **受講コース管理**
  * 受講コース情報の登録
* **品質・堅牢性**
  * **バリデーション**による厳格な入力チェック
  * **例外ハンドリングの共通化**（例外発生時に一貫したエラーレスポンスを返却）
  * **JUnit / Mockitoによる自動テスト**（コントローラーやサービスのモックテスト）
* **デプロイ・自動化**
  * **Swagger UI**によるAPI仕様の可視化と動作確認
  * **GitHub Actions**を活用した、テスト・ビルド・AWS（EC2）へのデプロイ自動化

## 💡 こだわったポイント・学んだこと

### 🔧 実装における具体的な工夫

#### 受講生情報
* **実務を見据えた「論理削除」の採用**<br>
  卒業や退会となった受講生の情報について、データベースから物理的に削除するのではなく、将来的なデータ分析や集計（受講生数の推移やコースごとの卒業生割合の算出など）に活用できるよう、削除フラグ（`isDeleted`）を用いた論理削除を採用しました。また、SQLの条件制御により「在校生（アクティブなユーザー）のみ」に絞り込んだ検索ロジックも合わせて実装しています。
* **アノテーションを活用した厳格な入力バリデーション**<br>
  不正なデータがデータベースに登録されるのを防ぐため、Bean Validationを活用した入力チェックを徹底しました。
  * **受講生ID (`id`)**<br>
    予期せぬ文字列の混入を防ぐため、正規表現（`@Pattern(regexp = "^\\d+$")`）を用いて「数字のみ」の入力を許容する設計にしました。
  * **メールアドレス (`email`)**<br>
    `@Email` アノテーションを付与し、Eメールとして有効な形式（`@`の有無など）のみを受け付けるように制限しました。

#### 受講生コース情報
* **データの整合性を保つリレーション設計**<br>
  `studentId` を受講生情報のメインID（`Student.id`）と紐付けることで、受講生と受講コースの「1対多」の関連性を正しく構築しました。これにより、特定の受講生を検索した際に、その人物が紐付いている受講コース情報も同時に、かつ正確に一括取得できる効率的な検索ロジックを実現しています。
* **ユーザーの手間とミスを減らす日付の自動計算ロジック**<br>
  受講期間を1年間とする仕様に基づき、コース開始日時（`courseStartAt`）が入力された際、システム側で自動的にその 1 年後を計算してコース終了日時（`courseEndAt`）に設定するビジネスロジックを実装しました。Java 8以降の推奨APIである `LocalDateTime` を活用し、手動入力による整合性エラー（開始日より前の日付が終了日に入力される等）を未然に防ぐ堅牢な設計にしています。

#### 受講生コース状況（ステータス管理）
* **正規表現を用いたステータスの厳格化と親切なエラーハンドリング**<br>
  受講の進捗状況を「仮申込」「本申込」「受講中」「受講終了」の4パターンに厳格に限定しました。正規表現（`@Pattern`）を活用し、定義外の不正な文字列が入力された際には、単に拒否するだけでなく「どの文字が有効か」を明記したエラーメッセージを返却する仕組みにしています。これにより、ユーザー（またはAPIクライアント）が開発者の手を煩わせることなく、メッセージを見て自己完結的に正しい入力へ修正できるよう、UXとシステムの堅牢性の双方に配慮しました。
* **受講状況の正確なトラッキング（紐付け設計）**<br>
  `CourseStatus` の `courseId` を、受講コース情報のメインIDと連動（リレーション）させました。これにより、「誰が」「どのコースを」「今どんな状態（ステータス）で受講しているか」をデータベースから正確、かつ芋づる式に高速で検索・抽出できる柔軟なデータ構造を実現しています。
